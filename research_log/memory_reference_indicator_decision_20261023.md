## 1. 확정한 운영 방침

사용자 지시: “일단은 참고 지표로서 보존을 하고, 나중에 여건이 된다 하면 추가적으로 구현을 하는걸로 진행하자.”

- 공식 평가는 압축률·압축 시간·압축 해제 시간의 3지표를 유지한다. [프로토콜 v2](../research_protocol_v2.md)와 [현재 설정](../config/experiment_config.json)이 계속 공식 기준이다.
- Memory는 참고·검증 지표로 보존한다. 현재 설정의 `memory.status=validation_only`와 보존 결과의 `score_inclusion=false`를 유지한다.
- Memory를 공식 종합 점수·정답 생성·모델 학습·Smart Mode 선택에 추가하지 않는다. 기존 3지표 Pilot·정답·모델을 유지한다.
- 기존 원시 측정값·metadata·환경 기록·실패·독립 감사·후보 분석·측정 및 분석 코드를 보존한다. 과거 실험에서 memory가 없는 항목에 값을 추정하거나 보충하지 않는다.
- Memory 추가 구현·새 측정·공식 4지표 전환은 여건이 마련됐을 때 재검토할 보류 과제다. 재개 시점은 정하지 않으며 자동 추가 실행이나 정기 측정을 설정하지 않는다.
- 당장의 구현 우선순위는 기존 3지표 시스템의 완성으로 옮긴다.

이 결정은 memory의 모든 활용 가능성을 부정하는 판단이 아니다. 현재 관측 근거와 사용자 우선순위에 따라 공식 편입을 보류하고 참고 자료를 남기는 선택이다.

## 3. 참고 지표의 사용 범위

보고서에서 memory를 다룰 때는 측정 경로·환경·변동과 안정성 미충족·효용 미확인 결과를 함께 제시한다. 현재 정의는 지정 worker 경로의 전체 프로세스 peak이며 압축기의 순수 할당량이나 Smart Mode 전체 실행의 메모리 상한을 뜻하지 않는다.

후보 4지표 score·정답·regret는 검증용 분석으로 남긴다. 이를 공식 4지표 결과나 새 모델 성능으로 표시하지 않는다. 참고 지표 보존을 이유로 일반 압축 실행에 memory 측정을 추가하지 않는다.

## 4. 여건이 마련됐을 때 재개할 과제

1. 사용 목적·메모리 측정 대상·적용 환경과 입력 범위를 다시 명시한다.
2. 시간 변동과 memory 변동의 영향을 구분하고, 허용 오차·선택 효용·판정 기준을 새 실험 전에 고정한다. 기존 미충족 결과를 통과시키기 위한 소급 기준 변경은 하지 않는다.
3. 별도 버전·출력 경로에서 측정·검증하고 실패와 불리한 결과를 함께 보존한다.
4. 새 근거로 공식 채택을 다시 검토한다. 프로토콜·가중치·runner·schema·정답·새 모델과 평가를 갖춰야 공식 전환이 가능하며, 이번 선택은 그 전환의 사전 승인이 아니다.

구체적인 추가 구현이나 재측정 일정은 현재 확정하지 않는다.
