## 확인할 질문

특징 계산에서 관찰된 개선이 파일 읽기·예측·압축·복원 검증·저장까지 포함한 상주 모델 경로에서도 유지되는가? 개선된 자동 선택의 가상 정책 비용이 같은 시점에 측정한 고정 zstd보다 낮아지는가? 두 질문을 따로 판정한다. 특징 계산이 빨라져도 zstd보다 유리하다고 미리 결론 내리지 않는다.

기존 개발 corpus 전체와 기존 가상 정책·모델 전체를 유지한다. 주 후보는 잠근 `both_numpy` 그대로다. 보조 후보 재선택·모델 학습·가중치/시나리오 조정은 없다. 공식 v2 모델의 외부 평가나 제품 CLI/GUI 채택으로 취급하지 않는다.

## 세 경로를 같은 조건에서 실행

| 경로 | 통계 특징 | 모델 | 압축 |
|---|---|---|---|
| reference | 동결 원래 함수 | 기존 해당 모델 | 실제 예측한 하나 |
| both_numpy | 동결 결합 후보 | 같은 모델 | 실제 예측한 하나 |
| fixed_zstd | 계산하지 않음 | 사용하지 않음 | zstd 하나 |

기존 연구 package 엔진의 동작을 복사·잠그고 특징 함수 바인딩만 바꾼다. manifest schema/이름·hash·codec 설정·복원 검증·파일 쓰기는 동일하다. 입력 frame 준비도 기존 동결 함수를 사용한다. 고정 예측은 실행 후 일치 검사에만 사용하고 예측 계산을 대신하지 않는다. 모델별 별도 worker 안에 모델을 상주시킨다. 로딩·프로세스 시작 시간은 이번 비용 범위 밖이다.

압축 구간은 원본 읽기 직전부터 payload와 manifest 저장·닫기까지이며 특징/예측·선택한 압축·복원 검증·hash를 포함한다. 복원 구간은 저장 manifest/payload 읽기부터 hash·복원·검증·파일 쓰기·닫기까지다. 마지막 독립 saved bytes 대조는 기존 엔진과 같이 timer 밖에서 반드시 실행한다. prepared trial 디렉터리 생성도 timer 밖이다. 실제 `smart_compress.py`의 제품 package/CLI와 같은 엔진이라고 주장하지 않는다.

## 순서와 저장

각 모델·파일에서 warmup triplet 뒤 여섯 본 triplet을 실행한다. 가능한 세 경로 순서 여섯 개를 파일마다 한 번씩 사용한다. 각 경로의 첫째/둘째/셋째 위치와 두 경로 간 선행 횟수가 균형을 이룬다. 모델/파일/반복/arm별 새 디렉터리를 쓰고 warmup 산출물도 보존한다. shuffle seed·모델 순서·전체 schedule은 결과를 보기 전에 고정한다. 호출 수는 준비 코드가 계획과 입력 목록으로 계산해 coverage.json에 기록한다.

파일 쓰기와 복원 파일 보존 때문에 기존 실측 package 크기·원본 크기를 사용한 새 출력 용량 추정치를 남긴다. 실제 실행 전 여유 공간은 추정치의 두 배와 1GiB 합 이상이어야 한다. 추정치는 파일시스템 overhead·새 bytes/시간 실측이 아니며 공간이 모자라도 기존 결과를 삭제하지 않는다. OS cache, 전원/동시 작업의 미확인 상태, warmup 효과는 한계로 남긴다. fsync·전송·모델 배포/저장·memory/energy 비용은 범위 밖이다.

## 판정과 검증

주 최적화 지표는 각 triplet의 상대 압축 경로 시간 차이를 파일별 중앙값→원본 그룹 내 평균→그룹 동일 비중 평균→전체 모델/시나리오 조건 동일 비중 평균으로 계산한다. 음수면 이 개발 corpus에서 전체 압축 경로로 개선이 이어졌다고 해석한다. 각 조건의 원시 ns 차이와 복원/합계 지연도 모두 보고한다.

가상 비용은 매 trial에서 `ks*H*package_bytes + kc*compression_ms + kd*N*restoration_ms`로 계산한다. ns를 ms로 변환하고 **trial 비용을 먼저 계산한 뒤 중앙값**을 구한다. 서로 다른 반복의 성분별 중앙값을 비용에 넣지 않는다. 각 시나리오/모델에서 후보−참조·후보−고정 zstd·참조−고정 zstd를 pair로 집계한다. 시나리오별 비용 points를 섞어 하나의 절감률을 만들지 않는다. zstd보다 저렴하다는 조건별 표시는 그룹 동일 비중 paired 비용 차이가 음수이고 파일별 비용 중앙값 합의 후보/zstd 비율이 1 미만일 때만 한다.

사전 gate에서 원본 hash·정확 builtin feature/float.hex/frame·기존 모델의 선택/확률을 확인한다. 매 trial은 실제 예측·한 압축기 실행·복원 검증을 거친다. 참조/후보의 payload·manifest bytes/크기와 복원 bytes는 정확히 같아야 한다. 원시 기록을 다시 읽는 독립 감사가 schedule·순서·시간·프로세스·모든 저장 파일·집계를 확인한다. 실패·악화·동점·부분 triplet도 보존하고 실패 반복만 재시도하지 않는다.

이 단계는 실측 준비다. 계획 동결·commit 다음에 격리 실행부와 독립 감사를 구현하고 인위적 입력으로 검증·commit한다. 그 이후에만 새 실측을 수행한다. 공식 특징 코드/score/모델/config와 memory 보류 방침은 유지한다. 최종 일반화 평가는 아직 사용하지 않은 원본 그룹이 필요하다.
