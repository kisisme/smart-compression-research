# 사용 조건에 근거한 후보 목적 함수 v1

상태: **후보 수학 설계 완료 / 공식 채택·운영 계수·구현·실측·모델 전환 미완료**. 작성일 2026-10-30.
사용자가 사용 상황 선택을 위임했으므로 기존 Archive·Balanced·Fast Access를 유지한다.
주후보는 **보관·압축·복원의 생애 총비용**, 비교 대안은 **시간 제한을 만족한 후보 중 크기 최소화**로 정한다.
기존 공식 기준은 [프로토콜 v2](../research_protocol_v2.md)와 [활성 설정](../config/experiment_config.json)이다.
이 문서는 공식 기준을 대체하지 않는다. [기계 판독 명세](usage_objective_spec_v1.json)를 함께 보존한다.

## 1. 설계 이유와 범위

[기존 Pilot 분석](pilot_tradeoffs_20261029.md)은 다른 압축기의 크기 이점과 zstd의 시간 이점이
함께 존재함을 보여 준다. 그 결과에서 특정 선택 비율을 얻는 가중치를 채택하지 않는다.
새 함수는 압축 한 번과 복원 여러 번, 보관 기간에 따른 저장 비용을 명시적으로 표현한다.
보관 기간·복원 횟수는 **사용 조건**이며 새로 측정한 압축 성능 지표가 아니다.
Memory는 [참고 지표 유지 결정](memory_reference_indicator_decision_20261023.md)에 따라 별도로 남긴다.

현재 숫자로 고정할 수 있는 실제 보관 기간·복원 횟수·지연 허용치·비용 교환비 근거는 없다.
따라서 운영 profile의 값은 `null`로 두고 임의의 현실 사용량처럼 기록하지 않는다.
이는 사용자의 추가 답변을 기다려야만 수학 구현을 진행할 수 있다는 뜻은 아니다.
명시적으로 제공한 가상 scenario로 순수 계산부를 구현·검산할 수 있으며 실제 실험 profile은 별도로 고정한다.

## 2. 주후보: 생애 총비용

파일 하나와 알고리즘 a에 대해 다음을 사용한다.

| 기호 | 의미 | 단위 |
|---|---|---|
| B_a | 압축 frame의 실제 크기 | bytes |
| T_c,a | 압축 시간 | ms |
| T_d,a | 전체 복원 한 번의 해제 시간 | ms |
| H | 보관 기간 | day |
| N | 그 기간의 기대 전체 복원 횟수 | count |
| k_s | 저장량·기간의 정책상 비용 계수 | 비용점수 / (byte·day) |
| k_c, k_d | 압축·해제 지연의 정책상 비용 계수 | 비용점수 / ms |

J(a | θ) = k_s H B_a + k_c T_c,a + k_d N T_d,a

최소 J를 선택한다. 세 항은 모두 같은 비용점수 단위다. 계수 합이 1일 필요는 없다.
실제 금전 비용을 주장하지 않으며 wall time을 CPU 사용량이나 전력량으로 간주하지 않는다.
압축은 처음 한 번, 복원은 N번, 보관 크기와 비용 계수는 일정하다고 가정한다.
재압축·부분 복원·계층별 가격·할인·보관 중 크기 변화는 이 단순 모델 범위 밖이다.

기존 함수의 ln(T/T_min)은 가장 빠른 후보 대비 배수 차이를 벌점으로 쓴다.
새 후보는 사용 조건에 따라 절대 시간 비용과 저장 이득을 비교한다.
압축률은 B_a/원본 크기이므로 같은 파일의 후보 비교에서는 B_a로 저장 비용을 계산할 수 있다.
파일 크기가 다른 경우 비용도 달라지는 것이 의도된 동작이며 이를 단순 평균 압축률과 혼동하지 않는다.

H,N,각 계수는 유한한 비음수이고 적어도 하나의 유효 계수 k_s H, k_c, k_d N이 양수여야 한다.
저장 목적의 기본 profile은 k_s H > 0을 요구한다. 시간만의 목적은 별도 profile로 명시한다.
측정값은 유한·양수·복원 검증 통과가 필요하다. 누락 값·bool·NaN·무한대·계산 overflow를 거부한다.
N은 기대 횟수이므로 소수일 수 있다. 값 누락을 0으로 바꾸거나 후보 라벨 빈도로 계수를 맞추지 않는다.

## 3. 언제 느리지만 더 작은 압축기가 유리한가

알고리즘 a가 b보다 작다고 가정한다: ΔB = B_b − B_a > 0.
시간 차이는 ΔT_c = T_c,a − T_c,b, ΔT_d = T_d,a − T_d,b로 둔다.

J(a) − J(b) = −k_s H ΔB + k_c ΔT_c + k_d N ΔT_d

따라서 a가 엄격히 유리한 조건은 다음과 같다.

k_s H ΔB > k_c ΔT_c + k_d N ΔT_d

k_s > 0일 때 보관 기간 경계는 다음과 같다.

H* = (k_c ΔT_c + k_d N ΔT_d) / (k_s ΔB)

H > H*이면 a가 유리하다. H* < 0이면 H ≥ 0인 전 구간에서 이미 유리하다.
H = H*는 동점이다. ΔB = 0 또는 k_s = 0이면 원래 비용 차이로 판정하며 나누지 않는다.

ΔT_d > 0, k_d > 0이면 복원 횟수 경계는 다음과 같다.

N* = (k_s H ΔB − k_c ΔT_c) / (k_d ΔT_d)

이 경우 a는 N < N*에서 유리하다. ΔT_d < 0이면 부등호 방향이 바뀌고,
ΔT_d = 0 또는 k_d = 0이면 N에 의한 변화가 없다. 음수 경계를 임의로 0으로 잘라 결과를 바꾸지 않는다.
모든 비용 계수를 같은 양수로 곱해도 순위는 같다. Bytes를 KiB로 바꿀 때 저장 계수를 함께 변환하면 비용도 같다.
수치적 표현과 정확 동점 규칙은 구현 버전에 기록하고, 선택 비율을 바꾸기 위한 epsilon을 추가하지 않는다.

## 4. 비교 대안: 시간 제한 아래 저장 크기 최소화

F = {a : verified=True, T_c,a ≤ τ_c, T_d,a ≤ τ_d}

a* = argmin_{a∈F} B_a

τ_c,τ_d는 미리 정한 유한한 양수의 ms 값이며 경계의 같은 값도 허용한다.
이 방식에서는 허용 시간 안의 속도 차이를 점수로 추가 보상하지 않는다.
허용 범위 안에서 더 작게 압축하는 것이 목적인 경우에 적합한 후보 정의다.
제약 때문에 선택할 수 없었던 후보도 원시 결과와 위반 이유를 보존한다.

- F가 비면 `constraint_unsatisfied`, `selected_algorithm=null`을 반환한다. 가장 빠른 후보로 몰래 대체하지 않는다.
- 필요한 측정이 없으면 `measurement_required`다. 누락을 0으로 보거나 조용히 후보에서 제거하지 않는다.
- 크기/비용이 정확히 같으면 기존 순서 gzip→bz2→lzma→zstd로 결정한다. 동점과 엄격 개선을 분리한다.
- Memory 제한은 활성화하지 않는다. 참고 peak는 codec 순수 할당량이나 Smart 전체 상한과 같지 않다.

네 후보를 측정한 뒤 구한 F는 offline oracle이다. Smart의 예측값만으로 실제 제한 준수를 보장할 수 없다.
Smart는 기존 순서대로 특징 추출→모드별 예측→압축기 하나 실행→복원 검증→저장한다.
실제 제한 위반은 따로 기록하며 검증을 통과한 파일과 deadline 준수 여부를 구분한다.
예측이 틀렸다고 나머지 압축기를 자동 실행하거나 한 번의 동기 실행 시간을 실시간 보장으로 표현하지 않는다.

## 5. 기존 세 모드의 역할

| 모드 | 이 설계에서 표현할 사용 조건 | 아직 정하지 않은 값 |
|---|---|---|
| Archive | 긴 보관 기간과 드문 복원에서 저장 이득이 누적되는 상황 | H,N,저장·지연 교환비 |
| Balanced | 명시한 대표 사용량에서 저장·압축·복원 비용을 함께 계산 | H,N,저장·지연 교환비 |
| Fast Access | 반복 복원 비용과 복원 지연 제한이 중요한 상황 | H,N,지연 교환비·허용 시간 |

위 역할은 방향이며 수치 가중치나 사용량의 확정이 아니다. 모든 profile에 같은 주후보 식을 적용하되 θ가 다르다.
후속 가상 scenario는 실제 사용 사실과 구분하고, 성능 결과를 보기 전에 모든 매개변수/변화 범위/선택 이유를 기록한다.
10% 이상의 다른 압축기 선택은 채택 조건으로 사용하지 않는다.

## 6. 수학 검산과 실제 연구의 구분

[문서·수학 검산기](verify_usage_objective_design_20261030.py)는 익명 후보 A/B의 인위적 숫자로
보관 기간·복원 횟수에 따른 순위 반전, 경계의 동점, 단위 변환·계수 스케일 불변성과 빈 제약 집합을 확인한다.
가상 입력과 계산값은 [검산 근거](usage_objective_design_checks_20261030.json)에 저장한다.
이 값은 gzip/bz2/LZMA/zstd의 측정값도 새 연구 결과도 아니다.
기존 Pilot 분석의 summary·산출물·source hash, 공식 설정·기존 모델/결과의 불변과 로컬 링크도 대조한다.
문서 작업이므로 기존 압축/학습/연구 실험·전체 테스트 suite를 재실행하지 않는다.

## 7. 후속 구현과 평가 계획

1. 새 후보 전용 순수 계산부를 별도 모듈로 구현한다. 공식 scoring.py·config·기존 라벨/모델은 유지한다.
   유효 입력·누락/비유한 값·경계/동점·빈 F·단위 변환·계수 스케일을 인위적 fixture로 검사한다.
2. 외부 사용 조건의 근거가 없으면 가상 scenario임을 명시하고 고정된 전체 scenario 집합을 먼저 기록한다.
   그 뒤 기존 Pilot을 탐색용 사본으로 계산한다. 비-zstd 비율에 맞춰 계수/파일을 고르지 않고 모든 결과를 보존한다.
3. 모델을 바꾸려면 새 정의별 정답·모델 버전을 만든다. 기존 모델은 v2 정답으로 학습했으므로 자동 전용하지 않는다.
   압축 전 통계 특징만 입력하고, 외부에서 고정한 profile이 모델을 선택한다.
   임의 H,N을 모델 입력으로 받는 방식은 현재 입력 계약을 바꾸므로 별도 설계가 필요하다.
4. Pilot 전체를 탐색했으므로 그 결과를 새 독립 시험 성능으로 주장하지 않는다.
   [실제 파일 평가 계획](unseen_evaluation_design_v1.md)과 최신 [진행 상태](../research_progress.md)를 기준으로
   corpus와 목적 함수/시나리오·학습 계획을 성능 확인 전에 고정한다. 최종 평가 자료를 계수 결정에 쓰지 않는다.
5. 항상 zstd, 학습 부분의 최빈 baseline, 새 모델, oracle을 같은 정의와 단위로 비교한다.
   선택 빈도·동점 외에 크기/압축·해제 시간·총비용·oracle regret·실패/제약 위반을 모두 보고한다.
   기존 로그 점수의 regret와 새 비용점수 regret의 크기를 직접 비교하지 않는다.
6. 별도 end-to-end 평가에서는 frame bytes 대신 package bytes를 사용하고, 특징 추출·모델 로딩/예측·
   복원 검증·디스크 I/O와 실제 반복 복원을 포함한 시간/비용을 새로 측정한다.
   Codec 시간을 전체 시간에 다시 더해 중복 계산하지 않는다. 기존 중앙값만으로 꼬리 지연이나 CPU/전력 비용을 추정하지 않는다.

GUI 수동 Compare의 원시 반복/점수/Demo/로그 저장 검증·전체 시각 QA와 실제 corpus 선정/동결·평가는 별도 미완료다.
이번 수학 설계 완료를 그 작업의 완료나 공식 score 전환으로 기록하지 않는다.
